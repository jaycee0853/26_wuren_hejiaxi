# 锥桶图像分类作业

## 项目概述

用 PyTorch 搭了一个 CNN，对锥桶图片做三分类（blue / red / yellow）。

---

## 项目结构

```
DL/
├── dataset/
│   ├── train/          # 训练集
│   ├── test1/         # 测试集1
│   └── test2/         # 测试集2
├── pth/                # 模型保存（训练时自动创建）
├── net.py              # 网络类定义
├── train.py            # 训练脚本
├── test.py             # 测试脚本
├── README.md
```

## 怎么跑

### 1. 训练

```bash
python train.py
```

训练过程中会打印：
- 每训练完一半batch打印一次loss和准确率（PPT要求的）
- 每个epoch结束再打印一次完整的
- 每个epoch在test1和test2上验证
- test1准确率创新高就保存模型

### 2. 测试

训练完后改 `test.py` 里的 `model_path`，然后：

```bash
python test.py
```

打印整体准确率和每个类别的准确率。

## 网络结构

```
输入 (3, 64, 64)
  │
  ├─ Conv2d(3→32, 3×3, padding=1) + ReLU + MaxPool2d  → (32, 32, 32)
  │
  ├─ Conv2d(32→64, 3×3, padding=1) + ReLU + MaxPool2d  → (64, 16, 16)
  │
  ├─ Conv2d(64→128, 3×3, padding=1) + ReLU + MaxPool2d → (128, 8, 8)
  │
  ├─ Flatten → 8192维
  │
  ├─ Linear(8192→256) + ReLU + Dropout(0.6)
  │
  └─ Linear(256→3) → 输出三个类别的分数
```

3个卷积层 + 2个全连接层 = 5层，不超过10层 ✓，全连接不超过3层 ✓

---

## 设计思路

### 为什么3层卷积

卷积层是一层比一层抽象的：第一层看边缘和颜色，第二层看纹理，第三层看形状。我试过4层，但训练集不大，4层参数太多过拟合更严重了，3层刚好。

### 为什么通道数32→64→128

越深的层特征越复杂，需要更多通道来表示。这个我是参考VGG的思路，它也是逐层翻倍通道数。

### 为什么padding=1

不加padding的话每层卷积尺寸会缩小2，算尺寸的时候特别容易搞错（我一开始就算错了...）。加了padding后只有池化层改变尺寸，算起来清楚多了。

### 为什么Dropout 0.6

训练集不大，不加Dropout的话模型直接把训练集背下来。一开始用0.3不够还是过拟合，改成0.5好一些，后来又加到0.6。

## 创新点

### 1. 数据增强

训练集加了随机水平翻转（50%概率）和随机旋转（±15度）。

我理解数据增强就是"免费扩充数据集"——翻转旋转之后对人来说还是同一个锥桶，但对模型来说就是新图了，泛化能力会好一些。

旋转角度我一开始设了30度，结果准确率反而掉了，后来改成15度就好了。应该是旋转太大锥桶变形太厉害了。

### 2. Adam优化器 + L2正则化 + 学习率调度

- 用Adam代替SGD，收敛快且稳定
- 加了weight_decay=5e-4（L2正则化），不加的话训练集99%测试集70%，典型的过拟合
- StepLR每30个epoch学习率缩小10倍，前期大步走后期小步走

### 3. 正确切换train/eval模式

训练时net.train()让Dropout生效，测试时net.eval()关闭Dropout。这个看起来简单但我一开始真的忘了...

## 踩坑记录

### 坑1：没做标准化，loss不收敛

一开始只做了Resize和ToTensor，没加Normalize。loss卡在0.6不动，准确率50%等于瞎猜。

后来查资料才知道ToTensor把像素值变成0-1全是正数，输入全为正的话梯度方向会偏，优化不动。加了Normalize映射到-1到1就好了。

**教训：标准化不是可选项，是必须的。**

### 坑2：BATCH_SIZE=1024太大

训练集1298张，1024的batch一个就装完了，每个epoch只更新一次参数，训练巨慢。改成64之后每个epoch更新约20次，快多了。

### 坑3：device写的"mps"在Windows上报错

原始代码写的`torch.device("mps" if ...)`，mps是Mac的GPU接口，Windows要用"cuda"。直接跑就报错了。

### 坑4：test.py类别数写错了

一开始我写了`range(2)`，因为之前只看到blue和red两个文件夹，后来发现还有yellow，改成`range(3)`就好了。

**教训：代码要跟实际数据对上，先检查数据集完整结构。**

### 坑5：forward手动加了softmax

我在fc2后面加了F.softmax，然后又用CrossEntropyLoss，loss一直不降。

后来才知道CrossEntropyLoss里面已经自带softmax了，再加一次等于做了两次，概率值被压缩得很小，loss就不正常了。

**教训：CrossEntropyLoss = LogSoftmax + NLLLoss，输出层不要加softmax。**

### 坑6：fc1的输入维度算错了

我把128\*8\*8算成了128\*4\*4，跑的时候维度对不上报错。搞了半天才反应过来池化了3次是64→32→16→8，不是64→32→16→4...

**教训：每一步的尺寸变化要仔细算，最好在纸上画出来。**

### 坑7：过拟合调了半天，test2还是波动

我试过加大Dropout（0.5→0.6）、加大weight_decay（1e-4→5e-4）、减少epoch（200→100），test1从100%降到了99.54%，但test2还是在95%左右波动，有时候94%有时候95%。

后来想明白了——test2只有140张图，随机性很大，几张图猜错就掉好几个百分点。而且训练集才1298张，模型很容易就"记住"了。对于这么小的数据集，95%+已经不错了，再调也提升不了多少。

**教训：小数据集的上限就在那里，不要过度调参，差不多就行。**

---

## 超参数

BATCH_SIZE=64，因为训练集1298张图，64的话每个epoch大概更新20次。一开始用的1024太大了，一个batch就把训练集装完了。

EPOCH=100，一开始设了200，但跑到后期越过拟合，改成100。

优化器用的Adam，lr=0.001（默认值），比SGD收敛快。weight_decay=5e-4，一开始1e-4不够还是过拟合，加大了。

StepLR每30轮学习率缩小10倍，前期大步走后期小步走。

Dropout=0.6，试过0.3不够，0.5好一些，0.6更好。

## 心得

这次作业最大的收获是理解了过拟合到底怎么回事。之前看PPT觉得"哦训练集好测试集差就是过拟合"，但真正跑出来训练集99%测试集70%的时候才体会到... 然后一个个试数据增强、Dropout、weight_decay，看着测试集准确率一点点涨上来，才真正理解这些方法是干嘛的。

还有就是数据预处理真的很重要。一开始没标准化loss就不动，我还以为网络写错了debug了半天，结果是预处理的问题。垃圾进垃圾出这句话是真的。

踩坑虽然痛苦但确实学东西最快。比如softmax重复那个坑让我真正记住了CrossEntropyLoss的内部结构，忘了eval模式那个坑让我理解了train/eval的区别。这些光看PPT真的记不住。
